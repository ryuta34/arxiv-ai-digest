# Skill Self-Play: Pushing the Frontier of LLM Capability with Co-Evolving Skills

| 項目 | 内容 |
|---|---|
| どんなもの？ | 大規模言語モデル（LLM）の自己学習プロセスにおいて、スキルをモジュール化して管理・進化させることで、タスクの多様性と検証の信頼性を両立させるフレームワーク「Skill Self-Play (Skill-SP)」を提案している。環境に縛られた狭いタスク空間と、フィルタリングに頼る広範だが低品質なデータ生成という従来手法のジレンマを解消する。 |
| 先行研究と比べてどこがすごい？ | 従来の「受動的なフィルタリング」ではなく、「能動的なスキルオーケストレーター」を用いて構造化されたタスクを生成する点に新規性がある。これにより、モデルは学習の最前線（learning frontier）を効率的に探索でき、ツール使用や論理推論において従来手法を大幅に上回る性能向上を達成した。 |
| 技術や手法のキモはどこ？ | プロポーザー（生成器）、ソルバー（推論器）、スキルコントローラー（ライブラリ管理者）の3者が強化学習ループを通じて共進化する点。スキルを「タスク生成の事前知識」および「検証のためのプログラム的バリデータ」として機能させ、成功した試行から新しいスキルを自動的に帰納・更新する仕組み。 |
| どうやって有効だと検証した？ | API-BankやBFCL（ツール使用）、ZebraLogic（論理推論）という2つの主要なベンチマークで検証を実施。Qwen3やMinistral、Graniteなど3B〜14Bパラメータのモデルに対し、一貫して大幅な性能改善を確認。また、スキルの帰納や定量的アブレーション研究により、各モジュールが性能に寄与していることを実証。 |
| 議論はある？ | 新規タスクの発見には、依然としてモデルが基礎的な能力を備えている必要がある。また、現状ではタスク生成のハイパーパラメータ（混合比率や難易度境界）が固定ヒューリスティックに依存しているため、今後はこれらを動的に学習・調整する仕組みが必要であると述べている。 |
