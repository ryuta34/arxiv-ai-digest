# Learning to Commit: Generating Organic Pull Requests via Online Repository Memory

| 項目 | 内容 |
|---|---|
| どんなもの？ | 過去のコミット履歴からリポジトリ特有のコーディングスタイルやAPI利用法を学習し、自然で「有機的」なプルリクエストを生成するフレームワーク「Learning to Commit」。LLMベースのコーディングエージェントが、専門の開発者のようにプロジェクトの慣習に適応することを目指している。 |
| 先行研究と比べてどこがすごい？ | 単なる静的なコード生成やテスト通過を目的とした従来ベンチマークと異なり、リポジトリの進化過程（履歴）をオンラインで学習する手法を導入した点。厳格な時系列分割によりデータリークを防ぎ、コードの品質・整合性を評価するマルチディメンションな指標を確立した。 |
| 技術や手法のキモはどこ？ | 「オンライン・リポジトリ・メモリ」を用いた監視付き対照リフレクション（supervised contrastive reflection）。エージェントが過去のコミットをブラインドで解決しようと試み、正解（oracle diff）と比較することで、自身の能力ギャップを埋めるためのスキルを抽出・蓄積する点。 |
| どうやって有効だと検証した？ | 大規模な実環境リポジトリから抽出した高精度なコミット履歴を用い、厳格な時間的カットオフを設定。エージェントが未知の未来のタスクにおいて、コードのローカライゼーション精度（File IoU）や効率性、冗長性の低減、スタイル整合性などを既存手法と比較し、大幅な向上を確認した。 |
| 議論はある？ | 現在はLLMによる評価に依存しているため評価のバイアスや不正確さが残る。また、スキルの蓄積が時として過度な慎重さを引き起こし、冗長なコードを生成する場合がある。今後はオープンソースのリポジトリへのスケーリングと、より堅牢な評価指標の構築が課題。 |
| 次に読むべき論文は？ | [13] [SWE-bench-CL](https://arxiv.org/abs/2507.00014) や [8] [RepoMem](https://arxiv.org/abs/2510.01003)、[6] [Commit0](https://arxiv.org/abs/2412.01769) など、リポジトリのコンテキスト学習や継続的学習に関する先行研究。 |
