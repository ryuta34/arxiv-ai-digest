# SWE-Prime: Fewer Trajectories, Better Performance

| 項目 | 内容 |
|---|---|
| どんなもの？ | ソフトウェアエンジニアリング（SWE）タスクにおけるAIエージェントの学習データを選別する、マルチ粒度の二段階SFTデータ選択手法「SWE-Prime」を提案した。成功した軌跡（Trajectory）の中にもノイズが含まれるという課題に対し、プロセス品質とデータ代表性に基づき高品質な軌跡とセグメントを抽出する。 |
| 先行研究と比べてどこがすごい？ | 従来手法が単にタスクの「成功」のみを基準に軌跡を収集していたのに対し、プロセス品質（ワークフロー、ツール使用効率、重複排除等）とセグメント単位の貢献度を評価することで、より低ノイズで学習効率の高いデータセットを構築できる。わずか10%のデータ量で、全データを用いた学習よりも優れた性能を達成した。 |
| 技術や手法のキモはどこ？ | 第一段階でプロセス・結果の品質とクラスタリングによる代表性を評価し、第二段階で連続するステップを意味的な「セグメント」に分割して、貢献度・学習可能性・リスクを基に損失計算の対象を絞り込む点。また、文脈を維持しつつ低品質な行為を学習から除外するマスク手法を採用した。 |
| どうやって有効だと検証した？ | SWE-Bench ProおよびVerifiedを用い、GLM-4.7-Flash、Qwen3-30B-A3B等のモデルで評価。既存の全成功データ（100%）を用いたSFTと比較し、選別された10%のデータで最大24.2%の相対的な性能向上を確認した。また、レッドダンシー低減やツール使用の改善など、モデルの挙動の質的向上も示証した。 |
| 議論はある？ | データ選別時のパラメータ（保持比率やスコア閾値）の感度分析を行っているが、選別されるデータの質は初期のデータセットに依存する。また、より小規模なデータで最適化が進む一方、どの程度のデータ削減が「最適」かについてはタスクの難易度やモデル能力との相関が残る。 |
