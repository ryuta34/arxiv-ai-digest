# IdeaAMBIG: Benchmarking Implementation-Critical Gaps in Research-Idea Specifications

| 項目 | 内容 |
|---|---|
| どんなもの？ | 研究アイデアの仕様書が実装可能（codification-ready）かどうかを評価し、不備を特定・解消するためのベンチマーク「IdeaAMBIG」を提案した研究。660件の証拠に基づいたインスタンスを用い、LLMが実装上の不備（曖昧さ、不完全性、不整合）を特定・解決できるかを評価する。 |
| 先行研究と比べてどこがすごい？ | 従来の研究はアイデアの質やコード生成自体を評価していたが、本研究は「実装前の仕様が十分か（実装準備ができているか）」に焦点を当てた点。単にエラーを指摘するだけでなく、具体的な「仕様の欠落」を特定し、それを埋めるための明確な質問や証拠収集アクションを生成できるかを評価する初めてのベンチマークである。 |
| 技術や手法のキモはどこ？ | 仕様書から「実装の不備（ブロッカー）」を特定するタスクと、その不備を解決するための「具体的なアクション生成」タスクを分離して評価する点。また、実世界（GitHubのissue等）と合成データ（制御された不備の注入）を組み合わせ、証拠に基づく「実装準備度」の評価を厳密に行っている点。 |
| どうやって有効だと検証した？ | 13種類のLLMを対象にベンチマークを実施。その結果、現状のモデルは不備の特定（Localization）に苦戦するが、一度不備が特定されれば解決策（Clarification）の提示能力は高いことを発見した。また、解決策を供給することで「実装準備度」が14%から98%へ向上することを示すオラクル実験を行った。 |
| 議論はある？ | 現在はAI、NLP、機械学習分野に集中しているため、他分野への適用には調査が必要。また、複数の欠陥が相互に影響する場合の評価や、マルチターンでの対話的な仕様確定などは今後の課題。モデルは「仕様の不備を指摘する」ことよりも「指摘された不備を埋める」ことの方が得意であるというボトルネックが明確になった。 |
